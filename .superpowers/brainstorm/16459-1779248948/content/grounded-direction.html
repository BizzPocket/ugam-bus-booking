What each piece comes from

  • Bilingual labels (Ugam · યાત્રા, My requests · મારી વિનંતી) — Khatabook / OkCredit pattern. Gujarati gets paired down a step, never as decoration.
  • Date strip on the tour card (Sat · 25 · May) — readable in one glance, the way printed bus timetables work.
  • Tabular numerics on every price, seat count, time stamp — Linear/Stripe pattern. Columns of ₹1,200 and 18/30 line up vertically across rows.
  • Sticky bottom CTAs (My requests, Open seat map) — 2026 thumb-zone pattern from muz.li. Action always in reach of right thumb.
  • Dense admin rows (56px, name + chips + 2 inline actions) — Khatabook ledger DNA. Call + Assign live in the row, not behind a tap-to-expand.
  • Seat-type chips (2 × DS, 1 × SS) — compact like SKU codes. Warm-accent variant signals "needs attention".
  • Status as dot + label (● 8 left in amber) — recedes when fine, draws eye when warm. No "BADGE PILL" everywhere.
  • Customer is light/paper, admin is dark/dense — same component library, two voices. Like Stripe vs Stripe Dashboard.
  • No costume — no serif headlines, no decorative circles on splash, no rotated stamps, no "FIG. 001 · AUTHENTICATION" filler.
Two things to lock with you before I write the spec:
  1. The customer = light, admin = dark split. Both still get a theme toggle, but the default mode flips by audience. OK?
  2. Bilingual labels are English-primary. The Gujarati sub-label is opt-in per surface (you'd see it on customer cards, not on admin dense rows). OK to do it that way, or do you want full bilingual across the admin side too?
